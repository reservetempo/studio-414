### The site look (tasks 29-55): facts every task shares

- Six themes, by id and name: `aqua` "Aqua" (today's look, which stays the base CSS), `win98` "Windows 98" (after 98.css), `system6` "Mac System 6" (after system.css), `nes` "NES" (after NES.css), `psone` "PlayStation" (after PSone.css), `dos` "DOS" (after Bootstra.386).
- The owner picks one theme and one colour (0-20, the existing palette; 0 "Classic" is the default) on the owner page. Both apply to the whole public site and to the owner page itself. Visitors can no longer change the colour: Display keeps only the fonts.
- Saved in the `site_settings` table as the row with key `look`, value `{ "theme": "<id>", "color": <0-20> }`. No row means `aqua` and colour 0.
- On both pages: `<html data-theme="<id>" data-color="<n>">`. Each theme other than Aqua is one file, `themes/<id>.css`, with every rule prefixed `:root[data-theme="<id>"]` so it overrides the Aqua base. Only the active theme's file is loaded. `?theme=<id>&color=<n>` on either page previews a look without saving or caching it.
- Themes are recreated in our own CSS on the existing markup; no library CSS is loaded. Each takes its shapes and its chrome font (title bars, buttons, labels, fields) from the original. Its colours come from the chosen colour's palette tokens, so every theme works with all 21 colours: text 4.5:1 or more, edges and borders 3:1 or more, checked for all 21. The visitor's Display font still sets the page text. Theme fonts are self-hosted under `fonts/<id>/` (OFL/MIT or similar only, licence noted in a comment) and declared in the theme file itself, so they only download when that theme is on.
- Themes restyle the chrome: windows, title bars, close buttons, buttons, fields, checkboxes, pop-up menus, the calendar, links lists, the comment box, focus rings, disabled states. Not the photo, the big 414 or "Opening soon!". Reduced motion stops any theme animation.

### Theme tasks (35-55): what each one does

The first theme tasks ran over the 150k budget, so each theme is now split into five parts, run in order for that theme (tasks for different themes can run in parallel; they only touch `themes/<id>.css` and `fonts/<id>/`):
- **Part 1a, windows:** the font setup (self-hosted `@font-face` in the theme file) and the window pieces: frame, title bar, close button, drag handle and grip, applied to the mailing-list card, the Display panel and the comment box.

- **Part 2, workshops:** the Workshops window (calendar with its ‹ ›, today and workshop-day pills, workshop links list, loading/failed/empty states) and the sign-up window (fields, checkbox, −/+, Pay/OK, All workshops, messages).
- **Owner 1:** the guide's owner-page part for the sign-in/loading/not-owner/error alerts, the menu bar, the section windows, the notices and the Look section, in an "Owner page" part of the same file.
- **Owner 2:** the owner page's Wallpaper section (photo well, spot box and handles, progress bar) and Workshops section (list view, capsules, disclosure triangle, sign-ups table, form group box).

Every theme task: start from `themes/README.md` (the guide) and the shared facts above; copy the original library's look (credit it in the file header) and map its colours onto the palette tokens; preview with `?theme=<id>` plus a few `&color=` values and at 375px (no horizontal scroll), `?theme=aqua` unchanged; check contrast for all 21 colours with a scratchpad script (not committed). Done when that part reads as the original library in every colour. Keep it small: download the library CSS to the scratchpad and grep it (never print it whole); don't read base CSS files whole (the guide gives the selectors); prefer computed styles over screenshots and take at most about five, at half scale where detail isn't needed. Most theme tasks still ran 150-210k, roughly in line with their tool calls, so stop at about 50 tool calls: push what's finished and report what's left. Owner-page previews need the stub described in the guide's section 5 (untracked copy, never committed, deleted after). If `git pull --rebase` refuses because another task's uncommitted files are in the working tree, run `git fetch origin`; if `origin/main` is already in HEAD's history, just push; otherwise stop and report.
